# Mobile UX review and fixes

Reviewed on 5 October 2026. Priorities: log a meal quickly, then understand remaining calories, protein, carbs, and fat.

This interaction review combines source inspection, component and regression tests, and an authenticated Today-page check in Dia at narrow desktop viewport widths. Screenshots confirm the nutrient rows, full-width target above nutrition, and restored calories ring. The initial meal expansion showed that ingredient names were repeated in its generated heading; component tests cover removal of that heading. Physical iPhone behavior, complete backend mutation flows, and user timing were not measured.

## Resulting task paths

1. **Remaining nutrition:** Today opens with the calories-left ring and separate rows for macros left or over target. Diary details are disclosed on expansion, and target selection sits above nutrition. Implemented; narrow desktop layout verified in Dia, physical iPhone verification pending.
2. **Photo or text:** Open the logger, attach a photo and/or describe the meal, estimate nutrition, then log from the pinned action. There is no source-selection stage or description/list switch. Implemented; native picker and keyboard verification pending.
3. **A saved food or meal:** In Library, tap Log or the row, adjust the default quantity if necessary, and log. No editing dialog or AI request is required. Implemented; authenticated end-to-end verification pending.
4. **Combine saved items:** In the logger, open Library, select foods/meals together, add them, and log. Quantities are adjusted in the meal review. Existing text, photos, and selected items remain intact. Implemented; regression-covered.
5. **Interrupted logging:** Close and reopen to resume the draft for that date. Clear draft is an explicit, confirmed action. Implemented; regression-covered.

## Verification

- Required lint, app type checking, formatting, unit/component tests, production build, and whitespace checks were run.
- The type-check script now follows the referenced TypeScript projects; the old root-only invocation did not check the app sources.
- Tests use local dummy Supabase environment values and mocked boundaries. They do not write to the backend. Happy DOM was added as a pinned development dependency for actual Vue event-handler tests.
- Regression coverage includes draft restoration, legacy migration, stale debounce writes, failed local draft storage, changed estimates, combined library/AI items, partial library-save failure, serving defaults, search/favorites/recency, compact entry markup, and remaining/over-target values.
- The production build reports a bundle-size warning and old Browserslist data. These are separate from the interaction fixes.

## Remaining checks and native handoff

- On a physical iPhone, verify the Photo picker offers the intended capture/library choices in Safari and installed PWA mode. Verify keyboard opening, sheet resizing, scrolling, focus restoration, VoiceOver announcements, and safe-area clearance. Desktop emulation alone would not establish these results.
- Exercise real authentication, photo upload, AI estimation, library reads/writes, offline saving, and reconnect synchronization. Unit tests do not establish server behavior or network latency.
- The retry queue still uses the existing backend write semantics. Its entries are not shown as provisional diary rows or included in remote daily totals. A future queue view should expose pending/failed entries and retry state without presenting provisional totals as synced.
- Native recipe editing should have an explicit Edit action and persistence for ingredient changes. The current quick-log adjustment changes only the logged portion.
- For native deletion recovery, add undo backed by a recoverable delete operation. The current web flow retains confirmation and identifies the meal being deleted.
